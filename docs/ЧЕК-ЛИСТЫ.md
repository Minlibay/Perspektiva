# Чек-листы: спецификация и план подключения

Источник: папка `ЧК ИИ` (11 шаблонов чек-листов) и `ЧК ИИ\18.09` (размеченные образцы документов).
Состояние на 12.10.2026. Шаблоны чек-листов для тестов скопированы в
`backend/tests/fixtures/checklists/`. Образцы из `18.09` содержат данные клиентов, поэтому
в репозиторий не кладутся: тесты на них запускаются, только если задан путь `AUDIT_SAMPLES_DIR`.

## 1. Как устроена разметка

Каждое проверяемое поле документа обозначено **кодом**. Буквы в начале кода задают тип документа,
число — поле: `П4` — поле Плана, `А20` — поле Акта, `ОБ1` — поле Разбивки ОКВЭД.

- **В образцах `18.09`** код вставлен прямо рядом с полем: в Word — выделением цветом,
  в PDF-сканах — текстовой надписью поверх скана. По образцам видно, где в документе лежит поле.
- **В чек-листах** колонка «Комментарии» содержит формулу над кодами:
  `А20=Д2`, `Акт6 = Акт2 + 20 р.д.`, `1О2 = количество строк 1О10`.
- **Образцы ссылаются друг на друга.** Например, в Заключении рядом с наименованием организации
  стоит `Акт1`: это значит «должно совпадать с полем Акт1 Акта».

Образцы относятся к трём разным аудитам:

| Аудит | Документы в `18.09` |
|---|---|
| ООО «ДКИ Компрессорное оборудование», 2-й инспекционный контроль, июль–август 2026 | План, Приказ ЭГ, Разбивка ОКВЭД, Информация для подготовки, Акт, Протоколы НС, План КД, Отчет по КД, Заключение, оба Листа оценки, Сертификат (приложение), Бланк заявки |
| ООО «УТЕКО», ресертификация, 1 этап | Договор, Отчет 1 этапа, Отчет об устранении НС 1 этапа |
| АО «ПТС» | Сводный акт, Расчёт трудоёмкости |

Пакет ДКИ — сквозная цепочка документов, поэтому годится как регрессионный тест для чек-листов
План, Акт, ПН, ПКД, Отчет КД, Заключение и Листы оценки.

## 4. Чек-листы и правила

Всего 11 чек-листов, 89 пунктов. Способ проверки:

- **Д** — проверяет код: даты, числа, отметки, совпадение реквизитов;
- **И** — модель извлекает поле (сканы, свободный текст), сравнивает код;
- **С** — сверка формулировок по смыслу (модель);
- **Р** — ручная проверка (подписи на сканах).

Формулы приведены дословно из шаблонов.

### 4.1 План АУДИТА — `ИИ -План АУДИТА.docx` (тип `plan`, проверяется План)

|---|---|---|---|

## 5. Открытые вопросы к методологу

1. **Пункт 1 Плана.** По примеру шаблона утвердить План нужно *не позже* чем за 5 рабочих дней до начала
   аудита и *не раньше* даты Приказа (`ПР3`). Прежний код считал нарушением утверждение раньше чем за 5 дней.
   На образце ДКИ (Приказ 13.07, утверждение 17.07, начало 27.07) прежний код ставил NOK, новое правило — OK.
   **Принято по примеру шаблона, требует подтверждения.**
2. **Один код у разных полей:**
   - `З1`/`З2` — и в Бланке заявки, и в Заключении;
   - `П4` — и область, и сроки аудита в Плане;
   - `СВ5` — и режим работы, и рекламации в образце Сводного акта;
   - `СВ2` в чек-листе Сводного акта — и ОКВЭД, и режим работы.
3. **Коды без разметки в образцах:**

   | Код | Где встречается | Вероятное значение |
   |---|---|---|
   | `И13` | План, п.8 | `П13` |
   | `И2`, `И3`, `И5`, `И6` | ПН, ПКД | `Акт2`, `Акт3`, `Акт5` |
   | `А1` | Листы оценки | `А20` или `Акт1` |
   | `ЛОО332` | Листы оценки | `ЛОО33` |
   | `1Отчет2` | Отчет КД | `КД1` |
   | `З10`, `З14` | Заключение | в образце `З12`, `З13` |
   | `П16` | План | — |
   | `ПКД1`, `ПКД2` | ПКД | образец ПКД без разметки |
   | `СЕРТ2` | Акт | — |
   | `1Закл1`–`1Закл5`, `1З4` | Заключение 1 этапа | нет образца |

4. **Пункт 2 Акта** — что такое «Плану 2 этапа»?
5. **Фамилии «Говорков» и «Сукорская»** записаны прямо в правилах чек-листов Заключения. Предлагается
   вынести их в настройки (руководитель ОС и его заместитель).
6. **Не хватает документов для тестов:** Договор и доп. соглашение №3 ДКИ, Расчёт трудоёмкости ДКИ,
   образец Заключения 1 этапа, размеченный ПКД.

## 6. Архитектура подключения

1. **Реестр типов документов** (`backend/doc_types.py`) — тип ↔ код ↔ признаки распознавания.
   Файл определяется по содержимому, имя файла — запасной вариант.
2. **Реестр чек-листов** (`backend/checklists.py`) — тип чек-листа определяется по заголовку
   («Чек лист проверки …»), колонки таблицы — по заголовкам «Область проверки», «ОК», «NOK»,
   «Проблемные зоны». Заполнение идёт по найденным колонкам. Поэтому новые редакции шаблонов
   (добавленная колонка, переставленные пункты) не ломают разбор.
3. **Правила привязаны к тексту пункта, а не к номеру строки.** Функции `_plan_rule_id` и
   `_svod_rule_id` в `main.py` сопоставляют пункт шаблона с правилом. Правило может зависеть от
   формулы шаблона: например, пункт 1 Плана работает по новому правилу, только если в формуле есть `ПР3`.
4. **Целевая схема для новых чек-листов:** извлечь поля по словарю кодов (код — где возможно,
   модель — для сканов и свободного текста) → вычислить формулу → ОК/NOK с конкретными значениями
   в обосновании. Вердикт выносит код, а не модель. Поля Акта извлекаются один раз и переиспользуются
   семью чек-листами.
5. **Интерфейс:** весь пакет аудита загружается одним разом, система показывает таблицу
   «файл → тип документа» для подтверждения и запускает выбранные чек-листы.

### Что сделано на этапе 0

**Шаблоны чек-листов:**
- `checklists.detect_checklist_type` различает все 11 чек-листов. Раньше 8 новых определялись как
  «План», а «Акт» не распознавался совсем.
- `checklists.parse_checklist` находит колонки по заголовкам: новый План (7 колонок, первая пустая)
  разбирается в 12 пунктов вместо 0, Сводный акт — в 11 пунктов с номерами из шаблона.
- Заполнение ОК/NOK и проверка результата работают по найденным колонкам.

**План АУДИТА:**
- правила привязаны к тексту пункта;
- п.1 — новое правило даты утверждения (`ПР3 ≤ П8`, начало аудита ≥ `П8` + 5 р.д.);
- п.7 — исключения сверяются с Сертификатом (ИК) или Отчетом 1 этапа (серт/ресерт); если источника нет,
  действует прежнее правило допустимых исключений;
- пп.8 и 10 — заключительное и предварительное совещание проверяются по каждому адресу графика;
- детерминированные проверки берут текст Плана из поля 2, а не первый файл со словом «план» в имени.

**Сводный акт:**
- правила привязаны к тексту пункта, номера пунктов берутся из шаблона;
- №3 — сначала сверка с п.27 Акта (`А43`), если он заполнен;
- №8 — численность сверяется с Расчётом трудоёмкости (`ТР1`), если этого требует шаблон;
- №13 «Аутсорсинг» — новое правило: раздел обязан быть заполнен.

**Прочее:**
- распознанные, но ещё не поддержанные чек-листы возвращают понятное сообщение; если такой
  чек-лист загружен рядом с поддержанным, он пропускается с пометкой в сообщении результата;
- шаблоны чек-листов, загруженные в сессию, но не выбранные в поле 1, не используются как
  источники (раньше «Чек лист Акт» находился по содержимому как Акт аудита);
- в ответе `/api/process` появилось поле `document_types` — тип каждого загруженного файла.

**Известные ограничения (переходят на этап 1):**
- отбор источников для пунктов Плана по-прежнему идёт по словам в имени файла: правило со словом
  «план» берёт и «План КД»; реестр типов документов пока используется только в пп.1 и 7 Плана;
- скан Сертификата без OCR-текста не распознаётся — тогда п.7 Плана проверяется по перечню
  допустимых исключений, о чём сказано в обосновании.
